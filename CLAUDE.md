# GeoGame

GeoGame — браузерная игра-викторина по географии мира. Референс: Geography of the World (Atom Games Ent.). Цель: угадывать страны по контуру на карте, флагам, столицам, населению.

## Стек

Чистый HTML/CSS/JS, ES-модули, никаких фреймворков, никакого npm. Запуск через локальный сервер или Live Server (модули не работают через `file://`). Деплой на GitHub Pages: https://vkassu.github.io/GeoGame/

## Данные

restcountries.com API (v3.1). Запрос требует параметр `?fields=...`, иначе вернёт 400. Данные стран загружаются на лету при старте (кеш в `data/countries.json` пока не реализован). Язык интерфейса — RU/EN (переключатель в шапке, по умолчанию русский); русские названия стран берутся из `translations.rus`, английские — из `name.common`.

Столицы API отдаёт **только по-английски**, поэтому русские названия столиц лежат в отдельном файле данных `data/capitals_ru.json` (ключ — код страны `cca2`) и подгружаются в `fetchCountries`. Словарь покрывает все 246 столиц из API, поэтому страны из игры не исключаются — играется полный список. `capitalName` берёт русское название из словаря (с фолбэком на английское из API, если страну вдруг добавят новую).

Эффективный набор полей: `name, translations, capital, population, flags, cca2, region, languages, currencies, area, coatOfArms`. Это 11 полей, а `/all` ограничивает запрос 10 → `fetchCountries` делает **два запроса** (`API_URL` 7 полей + `API_EXTRAS_URL` 5 полей, оба с `cca2`) и сливает по `cca2`. Языки (`languages`) и валюты (`currencies`) API отдаёт **только на английском** — в темах «Язык»/«Валюта» ответы остаются английскими в обоих языковых режимах.

Фон-глобус: по умолчанию `img/earth.jpg` (сферическое фото Blue Marble, NASA Public Domain, 2048×2048), подключается через CSS `body::after` по переменной `:root{--earth-bg}`. При старте `js/bg.js` (`initEarthBackground`, вызывается первой строкой `init()` в main.js) пробует загрузить более качественный вариант из интернета (список URL в `REMOTE_URLS`). При успехе обновляет CSS-переменную `--earth-bg` — `body::after` перерисовывается без перезагрузки. При ошибке/офлайн — остаётся локальный файл. **Грабли:** Wikimedia `upload.…/thumb/` отдаёт только фиксированные bucket-ширины (1280/1920 ок; 2048/2560/3000/4096 → HTTP 400) и режет запросы без contact-User-Agent; оригинал качается через `Special:FilePath`. См. PROMPTS_LOG #14.

## Структура проекта (фактическая)

- `index.html` — единственная страница: экраны настройки (Регионы `#start-screen` / Темы `#topics-screen` / Количество `#count-screen`) + игра `#game-screen` + результат `#result-screen`, переключаются классом `.active`.
- `css/style.css` — все стили.
- `js/data.js` — слой данных: запрос к API (`fetchCountries`, два запроса + слияние по `cca2`) и геттеры полей страны. Сырые геттеры (`ruName`/`engName`/`capitalName`/`hasCapital`/`languageName`/`currencyName`/`nativeNameStr`/`hasCoatOfArms`/`codeToEmoji` и `has*`-предикаты) + **lang-aware обёртки** (`getName`/`getCapital`/`getPopulationFormatted`/`getAreaFormatted`), выбирающие RU/EN по `getLang()`. Без DOM и без игровой логики.
- `js/main.js` — точка входа: игровой `state`, конфиг тем `TOPICS` и регионов `REGIONS`, поток настройки (Регионы/Темы/Количество), логика вопросов, единственное место работы с `localStorage`.
- `js/ui.js` — слой представления: переключение экранов и заполнение DOM. Без игровой логики и без state.
- `js/i18n.js` — интернационализация: текущий язык (`getLang`/`setLang`), словарь UI-строк и `t(key, vars)`, `applyI18n()` (по `data-i18n`), словари `TOPIC_LABELS` / `TOPIC_QUESTIONS` / `REGION_LABELS`.
- `data/capitals_ru.json` — словарь русских названий столиц (`cca2` → название).
- `img/earth.jpg` — спутниковый снимок NASA (Public Domain), фон-глобус в `body::after`.

Разделение `main.js` / `ui.js` заменяет изначально планировавшийся `js/game.js`.

## Темы вопросов

Тема = что показывается и что угадывается. Записи в объекте `TOPICS` (`js/main.js`). Несколько тем могут быть включены одновременно — для каждого вопроса тема выбирается случайно из активных.

1. **Страна по флагу** (`country`) — показывается флаг, выбрать название страны из 4 вариантов.
2. **Столица** (`capital`) — показывается название страны, выбрать столицу из 4 вариантов.
3. **Страна по столице** (`countryByCapital`) — показывается название столицы, выбрать страну из 4 вариантов.
4. **Население** (`population`) — название страны → выбрать форматированное население (`populationFormatted`, напр. «6,6 млн»). `valid`: `population > 0`.
5. **Площадь** (`area`) — название страны → площадь (`areaFormatted`, напр. «488 100 км²»). `valid`: `area > 0`.
6. **Язык** (`language`) — название страны → официальный язык (`languageName`). Значения **на английском** (ограничение API). `valid`: `hasLanguages`.
7. **Валюта** (`currency`) — название страны → название первой валюты (`currencyName`, на английском). `valid`: `hasCurrencies`.
8. **Самоназвание** (`nativeName`) — текст-промпт с самоназванием (`nativeNameStr`, не-английское `name.nativeName`) → выбрать страну. `valid`: `hasNativeName`.
9. **Герб** (`coatOfArms`) — изображение герба (`prompt.type === "coa"`) → выбрать страну. `valid`: `hasCoatOfArms`.

Темы 4–9 **не включены по умолчанию** (`DEFAULT_TOPICS` = только первые три) — игрок выбирает их вручную на Шаге 2.

**Два типа тем (архитектура):**
- **Тип А — «назови страну»** (`answer` = `getName`): `country` (`prompt` флаг), `countryByCapital` (`prompt` текст столицы `getCapital`), `nativeName` (`prompt` текст самоназвания `nativeNameStr`), `coatOfArms` (`prompt` герб).
- **Тип Б — «назови параметр»** (`prompt` = `{ type: "text", text: getName(c) }` — название страны на текущем языке, `answer` = параметр): `capital` (`getCapital`), `population` (`getPopulationFormatted`), `area` (`getAreaFormatted`), `language` (`languageName`, EN), `currency` (`currencyName`, EN). Игрок видит **название страны** и выбирает её параметр — страна называется явно, а не угадывается по флагу.

Каждая запись `TOPICS[key]`: `get label()`, `get question()` (геттеры, lang-aware), `prompt(country)`, `answer(country)`, `valid(country)`.

### Поток настройки игры — 3 экрана

Старт партии разбит на три экрана (вместо прежних «режим + сложность»):

- **Шаг 1 — Регионы** (`#start-screen`): 5 регионов (`REGIONS`: Европа/Азия/Африка/Америка/Океания → `country.region` = Europe/Asia/Africa/Americas/Oceania). Тап по ячейке вкл/выкл. Кнопки «Очистить всё»/«Выбрать всё». Счётчик «Доступно вопросов» = число пар **(страна × валидная тема)** в выбранных регионах (`questionPairs()`), поэтому растёт и от регионов, и от числа тем (напр. все регионы: 1 тема → 245, 2 → 489, 3 → 733). Кнопка **«Начало»** → Шаг 3 (активна только если доступных вопросов > 0). Кнопка **«Темы»** → Шаг 2. «Назад» — заглушка (disabled).
- **Шаг 2 — Темы** (`#topics-screen`): список тем с зелёным/серым индикатором, тап вкл/выкл, «Очистить всё»/«Выбрать всё», «Назад» → Шаг 1. Опциональная боковая ветка.
- **Шаг 3 — Количество** (`#count-screen`): 10/25/50/75/100. Тап → старт партии. «Назад» → Шаг 1.

Сложность как концепция удалена. «Режим» удалён — вместо него набор тем.

Настройки сохраняются между сессиями (`geogame:setup:*`). Дефолты при пустом localStorage: все 5 регионов, все 3 темы, 10 вопросов.

**Рекорд** = максимальный XP за одну партию (один общий, ключ `geogame:bestXpPerGame`). Старая схема «рекорд по режиму» удалена.

Сквозная кнопка «На главную» (в шапке) видна на всех экранах, кроме Шага 1; во время идущей партии перед выходом запрашивает подтверждение.

### Язык интерфейса (RU / EN)

- Кнопка `#lang-btn` в `.topbar` (`position: absolute; right: 0`), показывает код языка, на который переключит (RU↔EN). Дефолт — `ru`.
- Ключ localStorage `geogame:lang` (`"ru"` | `"en"`). Читается в `loadFromStorage` (`setLang`).
- `switchLang()` при клике: `setLang(next)` → `localStorage` → `updateLangButton()` → `applyI18n()` → `renderStatus()` → `refreshSetupUI()`.
- Все строки UI билингвальны: статичные ноды — через `data-i18n="key"` + `applyI18n()`; динамические (`#status`, счётчик вопросов, баннер ответа, итог партии, кнопки количества) — через `t(key, vars)` при рендере; метки тем/регионов и тексты вопросов — через геттеры `get label()` / `get question()`, читающие `getLang()`.
- Ответы тем — lang-aware обёртки `getName`/`getCapital`/`getPopulationFormatted`/`getAreaFormatted` из `data.js`. **Исключение:** `languageName` и `currencyName` всегда английские (источник — API).

### Запланированные темы

- Карта: «Найти на карте», «Контуры», «Столица на карте» — требуют нового компонента (SVG/GeoJSON).
- «Плотность населения» — вычислима из `population` / `area`, отдельного источника не нужно.
- Темы на основе внешнего JSON (ВВП, продолжительность жизни и т.п. — World Bank).

## Соглашения в коде

- `state` и `localStorage` — только в `main.js`. UI-слой не знает про state.
- Ключи localStorage (актуальные): `geogame:setup:regions`, `geogame:setup:topics`, `geogame:setup:questionCount` (массивы/число настройки), `geogame:bestXpPerGame` (рекорд по XP за партию), `geogame:xpTotal` (общий XP), `geogame:gamesPlayed`, `geogame:lang` (RU/EN).
- Устаревшие ключи (больше не пишутся, старые значения игнорируются, не чистим): `geogame:bestScore:<mode>`, `geogame:difficulty`, `geogame:mode`.
- Новая тема добавляется как запись в объект `TOPICS` (`label`, `question`, `prompt`, `answer`, `valid`) — остальная механика обобщена и переиспользуется.
- `prompt(country)` возвращает дескриптор того, что показывать в вопросе: `{ type: "flag", country }`, `{ type: "text", text }` или `{ type: "coa", country }` (герб). `renderQuestion` в `ui.js` рисует флаг / текстовый блок / изображение герба (`.coa-img`) по этому типу; флаг и герб имеют фолбэк `svg → png → эмодзи`.
- Имя функции `nativeNameStr` (самоназвание) не конфликтует с ключом темы `TOPICS.nativeName` — это разные неймспейсы (функция в data.js / ключ объекта).
- `state.questions` — массив `{ country, topicKey }` (тема фиксируется на этапе сборки партии в `startGame`). Вопрос = уникальная пара (страна, тема) из `questionPairs()`; одна страна может встретиться под разными темами в одной партии.
- **i18n:** `TOPICS` и `REGIONS` используют геттеры `get label()` / `get question()` — читают текущий язык из `i18n.js` в момент вызова (не кешируют). Ответы тем — lang-aware обёртки из `data.js` (`getName`/`getCapital`/`getPopulationFormatted`/`getAreaFormatted`); `languageName`/`currencyName` всегда EN. Статичные строки в DOM — через `data-i18n` + `applyI18n()`; динамические (`#status`, счётчик вопросов, баннер ответа) — через `t(key, vars)` при рендере. Новый ключ localStorage: `geogame:lang`.

## Доменные факты

Дорого добытые знания о данных и окружении. Сюда заносить всё, что можно забыть и переоткрывать заново.

**Данные стран (restcountries.com API v3.1):**
- Запрос требует параметр `?fields=...`, иначе 400.
- Названия стран: `translations.rus.common` — русский, есть для всех 250 стран.
- Столицы в API — **только английские**. Русский словарь — `data/capitals_ru.json` (ключ `cca2`).
- Покрытие `capitals_ru.json` — все 246 столиц из API. Стран без столицы (`hasCapital` false) — 4. Фильтрация по столице игроков из игры не выкидывает.
- Флаги — `flags.svg` / `flags.png` (внешний CDN flagcdn.com, не файл в репо). Может транзиентно не загрузиться → `renderQuestion` откатывается `svg → png → эмодзи` (`onerror`-цепочка), чтобы не оставалась битая картинка.
- `country.region` — одно из `Europe / Asia / Africa / Americas / Oceania` (+ `Antarctic` — 5 сущностей, не используем). **Запрашивается через `?fields=...,region`** — без этого поля `country.region` приходит `undefined` и фильтр по регионам не работает (грабли из задачи #6). Распределение: Africa 59, Americas 56, Europe 53, Asia 50, Oceania 27.
- **Лимит `/all`: максимум 10 полей в `?fields=`**, иначе `HTTP 400` (`"requesting more than 10 fields"`). Нам нужно 11 → `fetchCountries` делает **два запроса** (`API_URL` 7 полей + `API_EXTRAS_URL` 5 полей, оба с `cca2`) и сливает по `cca2` (грабли из задачи #9).
- `languages` — объект `{ code: name }`, значения **на английском**. Покрытие 249/250.
- `currencies` — объект `{ code: { name, symbol } }`, значения на английском. Берём первую запись. 247/250.
- `area` — число (км²). Фактически у всех 250 > 0, но фильтруем `> 0` защитно.
- `coatOfArms` — `{ svg, png }` (CDN mainfacts.com). Есть у **222** из 250; у остальных — пустой объект. Рендер `prompt.type === "coa"`, фолбэк `svg → png → 🏛`.
- `name.nativeName` — `{ langCode: { common, official } }`, уже в поле `name` (отдельный запрос не нужен). Не-английское самоназвание есть у 210/250; `hasNativeName` отсеивает чисто англоязычные.

**Окружение:**
- ES-модули **не работают через `file://`** — нужен локальный сервер. Деплой на GitHub Pages работает.
- Целевые браузеры: десктоп Chrome/Edge/Firefox + Safari на iPad (на нём играет дочка Алексея).
- Тестируем открытием https://vkassu.github.io/GeoGame/ после деплоя. **Кеш браузера** — известная проблема: после деплоя обязательно Ctrl+Shift+R, либо положиться на cache-busting в `index.html` (`?v=...` на script и link).

**Дополнения от Claude Code:**

Слой данных:
- Эндпоинт `/all` отдаёт ~250 сущностей — это **не только суверенные государства**, но и зависимые территории (Гонконг, Реюньон, Гибралтар, Фолкленды, Аруба и т.д.). 246 со столицей; **4 без столицы** — `AQ` Антарктида, `MO` Макао, `BV` Остров Буве, `HM` Остров Херд и о-ва Макдональд (в режимах со столицей не участвуют, фильтр `hasCapital`).
- `country.capital` — это **массив**; берём `capital[0]`. У части стран несколько столиц.
- `capitals_ru.json` намеренно следует строке `capital[0]` из API, поэтому ряд столиц — официальные, а не «привычные»: Шри-Ланка → Шри-Джаяварденепура-Котте (не Коломбо), Боливия → Сукре (не Ла-Пас), ЮАР → Претория, Палестина → Рамалла, Бурунди → Гитега, Казахстан → Астана. Это не ошибки — при сверке учитывать.
- В `buildOptions` варианты **дедуплицируются по значению ответа** (`topic.answer(country)`); две страны с одинаковым ответом не попадут в варианты вместе. Дистракторы берутся сначала из выбранных регионов, при нехватке добираются из всех валидных по теме.
- Список сортируется по **английскому** имени (`engName`) в `fetchCountries`.

Окружение и тестирование:
- Превью-инструмент (preview MCP) по умолчанию открывает вьюпорт шириной **1px** → измерения `vw`/`%`/grid обманчивы, пока не вызвать `preview_resize` (задать width/height). 
- **Скриншоты в этом превью стабильно таймаутят** (баг рендерера, не нашего кода). Верстку проверять через `preview_eval` + `getComputedStyle`/DOM, а не скриншотом.
- Node локально имеет глобальный `fetch` — удобно проверять реальный ответ API через `node -e '...'` до выбора подхода (см. принцип №2 выше).

## Принципы работы со мной (для Cowork и Claude Code)

1. **Перед нетривиальной фичей — открыть нужный раздел `REFERENCE.md` и `Текущий статус` явно, а не по памяти.** Привычка обеих сторон. Снимает рассинхрон между «как должно быть» и «как сейчас».

2. **Перед выбором архитектуры под данные — сначала проверить реальные данные.** Сделать пробный запрос, посмотреть формат, покрытие, краевые случаи. Зафиксировать находки в разделе «Доменные факты». Не строить решение на догадках о структуре API.

3. **Один источник правды на каждый тип информации:**
   - Спека референса → `REFERENCE.md`
   - Статус и приоритеты → `CLAUDE.md` («Текущий статус»)
   - История промптов → `PROMPTS_LOG.md`
   - Доменные факты → `CLAUDE.md` («Доменные факты»)
   - Архитектура и соглашения → `CLAUDE.md` (этот файл)

   Если информация дублируется — заводим ссылку «см. раздел X», а не вторую копию.

4. **Cowork и Claude Code работают над одним кодом.** Конфликтов в правках не должно возникать, если каждый коммитит свои изменения и оставляет понятный след. Перед нетривиальной работой — `git status` на чистоту дерева.

## Документы проекта и правила git

**Файлы документации:**
- `CLAUDE.md` — этот файл. Архитектура, статус, доменные факты, принципы. Главный для project-level контекста.
- `REFERENCE.md` — спека референс-приложения (Geography of the World). Только «как должно быть в эталоне».
- `PROMPTS_LOG.md` — журнал промптов Claude Code. Формат внутри файла.

**Правила git:**
- Все три файла лежат в репозитории (не в `.gitignore`).
- **После любого нетривиального изменения `.md`-файлов** — Claude Code делает `git commit` с понятным сообщением (`docs: обновлён статус — фича X выполнена`, `docs(reference): убраны статусные пометки`, и т. п.) в той же сессии, когда правка сделана.
- Cowork может редактировать `.md`-файлы, но `git commit` не делает. Если Cowork внёс правки — в чате оставляет маркер `⚠ требуется commit`, Claude Code увидит при следующем заходе и закоммитит сам.
- Перед сложными правками — `git status` и `git pull` на чистоту дерева.
