# GeoGame

GeoGame — браузерная игра-викторина по географии мира. Референс: Geography of the World (Atom Games Ent.). Цель: угадывать страны по контуру на карте, флагам, столицам, населению.

## Стек

Чистый HTML/CSS/JS, ES-модули, никаких фреймворков, никакого npm. Запуск через локальный сервер или Live Server (модули не работают через `file://`). Деплой на GitHub Pages: https://vkassu.github.io/GeoGame/

## Данные

**Источник стран — локальный `data/countries.json`** (закоммичен в репо). Рантайм **больше не ходит в restcountries.com**: `fetchCountries` грузит один локальный файл — мгновенно, без внешней зависимости. Файл обновляется **вручную** скриптом `node scripts/fetch_countries.js` (делает два запроса к API, сливает по `cca2`, сортирует по `name.common`, перезаписывает `data/countries.json`). Язык интерфейса — RU/EN (переключатель в шапке, по умолчанию русский); русские названия стран берутся из `translations.rus`, английские — из `name.common`.

Столицы API отдаёт **только по-английски**, поэтому русские названия столиц лежат в отдельном файле данных `data/capitals_ru.json` (ключ — код страны `cca2`) и подгружаются в `fetchCountries`. Словарь покрывает все 246 столиц из API, поэтому страны из игры не исключаются — играется полный список. `capitalName` берёт русское название из словаря (с фолбэком на английское из API, если страну вдруг добавят новую).

Эффективный набор полей: `name, translations, capital, population, flags, cca2, region, languages, currencies, area, coatOfArms`. Это 11 полей, а `/all` ограничивает запрос 10 → **скрипт** `scripts/fetch_countries.js` делает **два запроса** (7 полей + 5 полей, оба с `cca2`), сливает по `cca2` и пишет в `data/countries.json`. Рантайм (`fetchCountries`) этот файл просто читает. Языки (`languages`) и валюты (`currencies`) API отдаёт **только на английском** — в темах «Язык»/«Валюта» ответы остаются английскими в обоих языковых режимах.

Фон (с #44): **ротация полноэкранных сюжетных сцен** из `img/backgrounds/` (4 WebP: columbus/silkroad/antarctica/amazon, локальные, коммитятся в репо). При старте — случайная, дальше каждые 5 минут следующая по кругу с плавным crossfade 1.5с. Реализация — `js/bg.js` (`initBackgroundRotation`, вызывается в `init()`): два слоя-псевдоэлемента `body::before` (`--bg-0`) и `body::after` (`--bg-1`), новая картинка пишется в скрытый слой, переключается класс `body.bg-toggle` → opacity-transition. ⚠️ url() в CSS-переменной резолвится относительно **таблицы стилей** (`css/`), поэтому `bg.js` строит **абсолютный** URL от `document.baseURI` (корректно и на gh-pages `/GeoGame/`). До загрузки первой сцены виден тёмный `#0a0a1a` (`body { background }`) — этого достаточно как фолбэка. Прежний `img/earth.jpg` (фолбэк через `--earth-bg`) удалён вместе с CSS-переменной (см. PROMPTS_LOG, perf-проход 2026-05-30): на боевом мы видим WebP в течение ~100ms старта, fallback-картинка не нужна. Прежний космос-стиль (круглый глобус снизу + звёзды + тёмный градиент) заменён сценами (#44). Историческое: `js/bg.js` существовал и был удалён в #18 (тянул Wikimedia-варианты по сети) — нынешний bg.js работает только с локальными файлами, без сети. Грабли Wikimedia — в PROMPTS_LOG #14/#17.

## Авторизация и облако

- **Авторизация:** Firebase Auth (Google Sign-In) через **`signInWithPopup`**. ⚠️ **НЕ использовать `signInWithRedirect`**: сайт на `vkassu.github.io`, а `authDomain` — `geogame-b7f3e.firebaseapp.com` (разные домены); браузеры режут стороннее хранилище → `getRedirectResult` приходит пустым и пользователя выкидывает незалогиненным (проверено: redirect ломает вход, #18 откатил на popup). Popup открывает auth-handler в отдельном окне и возвращает результат через postMessage — работает на десктопе и в обычном Safari на iPad (попап из жеста-клика). CDN ES-модули `firebasejs/10.14.1`, без npm. Вся работа с Firebase изолирована в `js/firebase.js`; `apiKey` в конфиге — **не секрет**, безопасно коммитить (безопасность — правилами Firestore + Authorized Domains в Console). Проект `geogame-b7f3e`. **Кеш-инвалидация:** `firebase.js` импортируется в main.js с `?v=...` (модули иначе не покрыты cache-busting) — при правке firebase.js поднимать версию в импорте.
- **Данные в облаке:** Firestore, коллекция `users/{uid}`, поля `xpTotal / bestXpPerGame / gamesPlayed / lang / inventory / achievements / dailyPrize / streak / dailyQuests` (#47). Запись всегда `setDoc(..., {merge:true})` — частичные обновления безопасны (поле, не переданное в вызове, не затирает облако).
- **Гостевой режим:** без входа всё работает как раньше — только localStorage. `state.user = null`.
- **Миграция:** первый вход (документ ещё не существует) переносит локальные `xpTotal / bestXpPerGame / gamesPlayed / lang / inventory / achievements / dailyPrize / streak / dailyQuests` в Firestore (`loadUserData`, #47). Последующие входы берут облачные данные и пишут их в localStorage (`applyUserData` в main.js — она же нормализует достижения через `initAchievements()` и в конце вызывает `refreshMenuScreen()` чтобы профиль/бейджи/бонус подтянулись под облако). Возврат гостевого прогресса в облако — только при самом первом входе.
- **Сохранение:** все вызовы гейтятся `if (state.user)`. `endGame()` пишет `xpTotal / best / games / inventory / streak / dailyQuests`; `persistAchievements()` пишет `achievements / inventory` (вызывается per-correct-answer в `handleAnswer`, при поп-апах достижений и в `endGame`/`finishTraining` — Firestore SDK сам коалесцирует близкие записи, ~25/партия для free tier); `claimDailyPrize()` пишет `xpTotal / inventory / dailyPrize`; `claimQuest()` пишет `xpTotal / inventory / dailyQuests`; `switchLang()` пишет `lang`; `resetProgress()` обнуляет документ (#41). См. #47.
- **Сброс прогресса:** кнопка «Сбросить прогресс» (`#reset-progress-btn` на стартовом экране) → `resetProgress()` обнуляет XP/рекорд/партии/инвентарь/выбор тем/достижения/**дейлик/стрик/задания** (`geogame:daily-prize`/`streak`/`daily-quests` — удаляются и обнуляются в state, #41) в localStorage и (если залогинен) в Firestore. Облако обязательно перезаписывается нулями — иначе следующий вход вернул бы прогресс.
- **Firestore rules (ручной шаг в Console, не в репо):** пользователь читает/пишет только свой документ — `match /users/{userId} { allow read, write: if request.auth.uid == userId; }`. Плюс в Console: включить Google в Sign-in method и добавить `vkassu.github.io` + `localhost` в Authorized Domains.
- **Не проверяемо в preview:** реальный OAuth-вход (popup на gstatic/Google), Firestore I/O, миграция — только на деплое. См. PROMPTS_LOG #15, #18.

## Структура проекта (фактическая)

- `index.html` — единственная страница: главное меню `#menu-screen` (первый экран: профиль + кнопки) + экраны настройки (Регионы `#start-screen` / Темы `#topics-screen` / Количество `#count-screen`) + игра `#game-screen` + информация `#info-screen` (карточка страны в контейнере `#info-card`) + энциклопедия `#encyclopedia-screen` (три вида-блока: `#enc-regions`/`#enc-countries`/`#enc-detail`) + задания `#tasks-screen` (три карточки: дейлик/стрик/квесты) + достижения `#achievements-screen` (4 секции-категории + шапка с суммарным бонусом) + результат `#result-screen`, переключаются классом `.active`.
- `css/style.css` — все стили.
- `js/data.js` — слой данных: загрузка стран из локального `data/countries.json` (`fetchCountries`) + подмешивание русских столиц/религий и геттеры полей страны. Сырые геттеры (`ruName`/`engName`/`capitalName`/`hasCapital`/`languageName`/`currencyName`/`nativeNameStr`/`hasCoatOfArms`/`codeToEmoji` и `has*`-предикаты) + **lang-aware обёртки** (`getName`/`getCapital`/`getPopulationFormatted`/`getAreaFormatted`), выбирающие RU/EN по `getLang()`. Без DOM и без игровой логики.
- `js/main.js` — точка входа: игровой `state`, конфиг тем `TOPICS` и регионов `REGIONS`, поток настройки (Регионы/Темы/Количество), логика вопросов, единственное место работы с `localStorage`.
- `js/ui.js` — слой представления: переключение экранов и заполнение DOM. Без игровой логики и без state.
- `js/i18n.js` — интернационализация: текущий язык (`getLang`/`setLang`), словарь UI-строк и `t(key, vars)`, `applyI18n()` (по `data-i18n`), словари `TOPIC_LABELS` / `TOPIC_QUESTIONS` / `REGION_LABELS`.
- `js/firebase.js` — авторизация и облако: Firebase Auth (Google, popup) + Firestore через CDN ES-модули (без npm). Экспорт `signInWithGoogle`/`signOutUser`/`onUserChanged`/`loadUserData`/`saveUserData`.
- `js/achievements.js` — система достижений (data-layer, без DOM и без игрового state): пороги (`MULTI_THRESHOLDS`/`GAMES_THRESHOLDS`/`XP_VOL_THRESHOLDS`), словарь `ACHIEVEMENT_DEFS` (ключ `"category:id"`, 26 достижений: region×5/topic×13/volume×2/mastery×6), `initAchievements`/`advanceAchievement`/`setAchievementProgress`/`getAchievementBonus`/`applyBonus`. Категории region, topic и volume дают `xpBonusPerLevel:1` (+1% за уровень, без потолка) — `getAchievementBonus` суммирует уровни всех def с `xpBonusPerLevel > 0`; volume вдобавок даёт сундуки; mastery — только сундуки, без XP-бонуса (#39).
- `js/levels.js` — система уровней/сложностей/разблокировок (data-layer, без UI и state): `XP_THRESHOLDS` (52, накопит. пороги; расширен с 50 в #43 под 13×4=52 разблокировки), `LEVEL_UNLOCKS` (уровень → разблокировки тем×сложностей; модульная переменная, строится из порядка тем через `initLevelUnlocks(Object.keys(TOPICS))` — вызывается в main.js), `getLevelFromXP`/`getXPForLevel`/`getXPProgress`/`getUnlockedDifficulties`/`getUnlockLevel`/`getUnlocksForLevel`.
- `data/countries.json` — **основной локальный датасет стран** (~250, слитые поля, отсортированы). Генерируется `scripts/fetch_countries.js`, коммитится в репо. Рантайм читает его вместо API.
- `scripts/fetch_countries.js` — Node-скрипт (CommonJS, запуск вручную): тянет restcountries, сливает, сортирует → `data/countries.json`.
- `data/capitals_ru.json` — словарь русских названий столиц (`cca2` → название).
- `data/religions.json` — словарь доминирующих религий (`cca2` → религия на EN, 244 страны; сливается в `country.majorReligion` в `fetchCountries`).
- `data/silhouettes/{cca2}.svg` — SVG-силуэты границ стран (237 шт, ~1 МБ; генерируются `scripts/build_silhouettes.js` из Natural Earth 50m GeoJSON, коммитятся в репо). Имена файлов в нижнем регистре. Рядом `data/silhouettes/index.json` — манифест (массив cca2 в ВЕРХНЕМ регистре), по нему `data.js` гейтит тему «Силуэт» (`hasSilhouette`). 13 стран без силуэта (нет отдельной геометрии в Natural Earth — заморские территории Франции GF/GP/MQ/RE/YT входят в геометрию FR, плюс мелкие острова BQ/BV/CC/CX/GI/SJ/TK/UM) — в теме не участвуют, силуэт для них физически невозможен. Тайвань (TW) с #45 включён: его `ISO_A2`=«CN-TW» (мусор), код берётся из `ISO_A2_EH` через `getCca2`. Рендер — `prompt.type === "silhouette"` в ui.js (`<img class="silhouette-img" src="data/silhouettes/{cca2}.svg">`, фолбэк «?»).
- `data/worldmap.json` — карта мира для темы «Найди на карте»: `{ w, h, countries: [{ cca2, d, bbox, c }] }`, где `d` — **уже спроецированный** SVG-путь (geoNaturalEarth1, 960×500), `bbox`/`c` — экранные bbox и центр крупнейшего контура. Генерируется `scripts/build_worldmap.js` из Natural Earth 50m (~1.1 МБ), коммитится в репо. **Покрывает все 250 стран (#45):** 237 с геометрией + 13 «dot-only» записей `{ cca2, c, dotOnly:true }` (без `d`/`bbox`) для стран без геометрии — их центроиды берутся из `data/missing_centroids.json`; в UI рисуются оранжевой точкой. Грузится лениво в ui.js при первом вопросе темы. **Проекция считается на этапе сборки → рантайм не тянет D3/внешние библиотеки** (#43). Рядом `data/worldmap_index.json` — манифест (массив cca2 в ВЕРХНЕМ регистре, все 250), по нему `data.js` гейтит тему (`hasMapFind`).
- `data/missing_centroids.json` — ручной словарь `{ cca2: [lon, lat] }` для 13 стран без отдельной геометрии в Natural Earth (заморские территории Франции + мелкие острова). Используется `build_worldmap.js` для добавления dot-only записей в `worldmap.json`. Для силуэтов НЕ используется (силуэт = форма, точкой не заменить).
- (исторически) `img/earth.jpg` — спутниковый снимок NASA, использовался как CSS-фолбэк фона (`--earth-bg`). Удалён в perf-проходе 2026-05-30: WebP-сцены грузятся быстро, тёмный `body { background:#0a0a1a }` достаточен на старте.
- `img/backgrounds/*.webp` — 4 полноэкранные сюжетные сцены (columbus/silkroad/antarctica/amazon), ротация фона (#44). Переведены PNG→WebP (q82, ~851 КБ суммарно вместо ~11.7 МБ). Локальные, коммитятся в репо.
- `js/bg.js` — ротация фоновых сцен с crossfade (`initBackgroundRotation`): два слоя `body::before`/`::after`, класс `body.bg-toggle`, смена каждые 5 мин. Только локальные файлы, без сети.
- `img/flags/{cca2}.svg` — флаги всех 250 стран (локально, ~2.7 МБ). `img/coats/{cca2}.svg` — гербы 222 стран (локально, ~39 МБ). Скачаны `scripts/download_assets.js`. Рендер — `localAssetImg("flags"|"coats", cca2, …)` в ui.js, фолбэк `svg → png → эмодзи/🏛`. **CDN flagcdn/mainfacts в рантайме больше не используются** (#26).
- `scripts/download_assets.js` — Node-скрипт (ручной запуск): качает флаги/гербы из CDN (URL берёт из `data/countries.json`) в `img/flags`/`img/coats`.
- `scripts/build_silhouettes.js` — Node-скрипт (ручной запуск): тянет Natural Earth 50m GeoJSON, строит SVG-силуэты в `data/silhouettes/` + манифест `index.json`. Код страны — `getCca2` (#45): `ISO_A2`, только если это валидный 2-буквенный код (regex `^[A-Z]{2}$`), иначе фолбэк `ISO_A2_EH` — ловит мусор вроде Тайваня («CN-TW»). Эвристика антимеридиана (сдвиг долгот при ширине bbox > 180° — для России/США/Фиджи); при нескольких feature на один код берёт самый крупный (AU = материк, а не о-ва Ашмор).
- `scripts/build_worldmap.js` — Node-скрипт (ручной запуск): тянет Natural Earth 50m GeoJSON, проецирует все страны geoNaturalEarth1 (формула d3-geo реализована **вручную, без npm**) в экранные координаты и пишет `data/worldmap.json` + `data/worldmap_index.json`. Код страны — тот же `getCca2` с валидацией формата (#45). Несколько feature на код сливаются в один путь; bbox/центроид — по крупнейшему контуру. Антимеридиан НЕ сдвигается (единая мировая проекция; автозум к крупнейшему контуру). После GeoJSON добавляет dot-only записи для стран из `data/missing_centroids.json`, которых не было в данных (#45).

Разделение `main.js` / `ui.js` заменяет изначально планировавшийся `js/game.js`.

## Темы вопросов

Тема = что показывается и что угадывается. Записи в объекте `TOPICS` (`js/main.js`). Несколько тем могут быть включены одновременно — для каждого вопроса тема выбирается случайно из активных.

1. **Найди на карте** (`mapFind`) — SVG-карта мира с выделенной оранжевым страной (`prompt.type === "mapFind"`) → выбрать страну из N вариантов. Тип А (назови страну), `answer` = `getName`. `valid`: `hasMapFind` — гейтится манифестом `data/worldmap_index.json` (**все 250 стран**, #45). Карта рендерится из **предварительно спроецированных** путей (`data/worldmap.json`, без D3 в рантайме); микрогосударства (bbox < 8px) и dot-only страны (13 без геометрии — `data/missing_centroids.json`) помечаются оранжевым кружком (для dot-only — фикс-зум 240×120 вокруг центроида); автозум к bbox страны (MIN 80, отступ 50%). С #46 — **первая тема в TOPICS**, открывается на уровне 1.
2. **Силуэт** (`silhouette`) — SVG-контур границ страны (`prompt.type === "silhouette"`, из `data/silhouettes/{cca2}.svg`) → выбрать страну из N вариантов. Тип А (назови страну), `answer` = `getName`. `valid`: `hasSilhouette` — гейтится манифестом `data/silhouettes/index.json` (237 стран; +Тайвань с #45; 13 заморских/островных без отдельной геометрии не участвуют — силуэт для них невозможен). Силуэт залит индиго (#4f46e5), фолбэк рендера — «?». С #46 — **вторая тема в TOPICS**, открывается на уровне 2.
3. **Страна по флагу** (`country`) — показывается флаг, выбрать название страны из 4 вариантов.
4. **Столица** (`capital`) — показывается название страны, выбрать столицу из 4 вариантов.
5. **Страна по столице** (`countryByCapital`) — показывается название столицы, выбрать страну из 4 вариантов.
6. **Население** (`population`) — название страны → выбрать форматированное население (`populationFormatted`, напр. «6,6 млн»). `valid`: `population > 0`.
7. **Площадь** (`area`) — название страны → площадь (`areaFormatted`, напр. «488 100 км²»). `valid`: `area > 0`.
8. **Язык** (`language`) — название страны → официальный язык (`languageName`). Значения **на английском** (ограничение API). `valid`: `hasLanguages`.
9. **Валюта** (`currency`) — название страны → название первой валюты (`currencyName`, на английском). `valid`: `hasCurrencies`.
10. **Самоназвание** (`nativeName`) — текст-промпт с самоназванием (`nativeNameStr`, не-английское `name.nativeName`) → выбрать страну. `valid`: `hasNativeName`.
11. **Герб** (`coatOfArms`) — изображение герба (`prompt.type === "coa"`) → выбрать страну. `valid`: `hasCoatOfArms`.
12. **Плотность населения** (`density`) — название страны → плотность (`getDensityFormatted`, напр. «97 чел/км²» / «97/km²»; `population/area`). `valid`: `hasDensity` (population>0 && area>0). Lang-aware.
13. **Религия** (`religion`) — название страны → доминирующая религия (`religionName`, EN-значения из `data/religions.json`). `valid`: `hasReligion`. Значения **на английском** (как языки/валюты). Различных значений ~7 (Christianity/Islam/Buddhism/Hinduism/Judaism/Irreligion/Folk religion) → на высоких сложностях вариантов меньше, чем 10 (дедуп по значению).

**Сложности и включение тем (#17A data + #17Б UI):** каждая тема имеет `difficulties` — массив `[{choicesCount:4},{6},{8},{10}]` (index 0..3, едины для всех тем через присваивание после `TOPICS`). Состояние тем — `state.setup.topicDifficulties` = объект `{ topicKey: -1..3 }`, где `-1` = тема выключена, `0..3` = выбранная сложность. **По умолчанию все темы выключены** (`DEFAULT_TOPIC_DIFFICULTIES` = все `-1`). На экране Тем у каждой темы 4 кнопки сложности `[1][2][3][4]` (`renderTopicList`): заблокированные (не открыты по уровню) серые/disabled и показывают «🔒 N» — уровень разблокировки (`getUnlockLevel(topicKey, diffIndex)` из `levels.js`, передаётся 5-м аргументом в `renderTopicList`; не i18n-зависимо), открытые — с обводкой и цифрой 1–4, выбранная — зелёная. Тап по кнопке = `selectTopicDifficulty(topicKey, idx)` (повторный тап по выбранной → выключает тему). Доступные сложности гейтятся уровнем игрока: `getUnlockedDifficulties(topicKey, getLevelFromXP(state.xpTotal))`. Система уровней/разблокировок — в `js/levels.js` (XP-пороги, `LEVEL_UNLOCKS`, `getLevelFromXP`/`getXPProgress`/`getUnlockedDifficulties`/`getUnlockLevel`).

**XP за правильный ответ зависит от сложности:** таблица `XP_BY_DIFFICULTY = [10, 15, 25, 40]` в `main.js` (4/6/8/10 вариантов соответственно). Прежняя константа `XP_PER_CORRECT = 10` удалена (balance-пасс 2026-05-30) — на лёгкой сложности награда не меняется, на 3 (10 вариантов) награда х4. Бонус достижений применяется поверх (`applyBonus`).

**Два типа тем (архитектура):**
- **Тип А — «назови страну»** (`answer` = `getName`): `country` (`prompt` флаг), `countryByCapital` (`prompt` текст столицы `getCapital`), `nativeName` (`prompt` текст самоназвания `nativeNameStr`), `coatOfArms` (`prompt` герб).
- **Тип Б — «назови параметр»** (`prompt` = `{ type: "text", text: getName(c) }` — название страны на текущем языке, `answer` = параметр): `capital` (`getCapital`), `population` (`getPopulationFormatted`), `area` (`getAreaFormatted`), `language` (`languageName`, EN), `currency` (`currencyName`, EN). Игрок видит **название страны** и выбирает её параметр — страна называется явно, а не угадывается по флагу.

Каждая запись `TOPICS[key]`: `get label()`, `get question()` (геттеры, lang-aware), `prompt(country)`, `answer(country)`, `valid(country)`.

## Соглашения в коде

- `state` и `localStorage` — только в `main.js`. UI-слой не знает про state.
- Ключи localStorage (актуальные): `geogame:setup:regions` (массив), `geogame:setup:topicDifficulties` (объект `{topicKey:-1..3}`), `geogame:setup:questionCount` (число), `geogame:bestXpPerGame` (рекорд по XP за партию), `geogame:xpTotal` (общий XP), `geogame:gamesPlayed`, `geogame:inventory` (объект `{chests}` — `hints`/`extraLives` удалены в #23; при чтении старых значений игнорируются), `geogame:lang` (RU/EN), `geogame:daily-prize` (объект `{lastClaimDate}` — дейлик, сброс по дате, #31/#37), `geogame:streak` (объект `{count,lastGameDate,milestonesClaimedAt}` — серия, #31), `geogame:daily-quests` (объект `{date,quests[]}` — задания дня, 3 тира, #31/#37), `geogame:achievements` (объект `{ "cat:id": {progress,level} }` — достижения, #36), `geogame:achievements-new` (`"true"` — флаг непросмотренных новых уровней для бейджа, #36). Устаревший `geogame:setup:topics` (массив тем) больше **не читается и не пишется** (заменён на `topicDifficulties`).
- Устаревшие ключи (больше не пишутся, старые значения игнорируются, не чистим): `geogame:bestScore:<mode>`, `geogame:difficulty`, `geogame:mode`.
- Новая тема добавляется как запись в объект `TOPICS` (`label`, `question`, `prompt`, `answer`, `valid`) — остальная механика обобщена и переиспользуется.
- **Порядок тем и уровни разблокировки.** `LEVEL_UNLOCKS` всегда строится динамически из `Object.keys(TOPICS)` через `initLevelUnlocks()` (вызов в `main.js` сразу после определения `TOPICS`). Отдельный захардкоженный список тем в `levels.js` не ведётся. Правило UI: порядок в `TOPICS` = порядок на экране «Темы» = порядок разблокировки (замки идут строго по возрастанию сверху вниз). С #46 первыми идут «Найди на карте» и «Силуэт» (открываются на уровнях 1 и 2 как стартовые/витринные темы); остальные в прежнем порядке от country до religion. Если меняешь порядок — `initLevelUnlocks` пересчитает уровни автоматически. При добавлении новой темы — вставлять в нужное место в `TOPICS`, `initLevelUnlocks` пересчитает уровни автоматически. Снаружи `levels.js` уровень-разблокировки доступны через `getUnlockLevel(topicKey, diffIndex)`, `getUnlockedDifficulties(topicKey, level)`, `getUnlocksForLevel(level)`.
- `prompt(country)` возвращает дескриптор того, что показывать в вопросе: `{ type: "flag", country }`, `{ type: "text", text }` или `{ type: "coa", country }` (герб). `renderQuestion` в `ui.js` рисует флаг / текстовый блок / изображение герба (`.coa-img`) по этому типу; флаг и герб имеют фолбэк `svg → png → эмодзи`.
- Имя функции `nativeNameStr` (самоназвание) не конфликтует с ключом темы `TOPICS.nativeName` — это разные неймспейсы (функция в data.js / ключ объекта).
- `state.questions` — массив `{ country, topicKey, difficultyIndex }` (тема и сложность фиксируются при сборке партии в `startGame`). Вопрос = валидная тройка (страна, тема, сложность) из `questionPairs()`; число вариантов ответа берётся из `TOPICS[topicKey].difficulties[difficultyIndex].choicesCount` (4/6/8/10). Одна страна может встретиться под разными темами в одной партии.
- **i18n:** `TOPICS` и `REGIONS` используют геттеры `get label()` / `get question()` — читают текущий язык из `i18n.js` в момент вызова (не кешируют). Ответы тем — lang-aware обёртки из `data.js` (`getName`/`getCapital`/`getPopulationFormatted`/`getAreaFormatted`); `languageName`/`currencyName` всегда EN. Статичные строки в DOM — через `data-i18n` + `applyI18n()`; динамические (`#status`, счётчик вопросов, баннер ответа) — через `t(key, vars)` при рендере. Новый ключ localStorage: `geogame:lang`.

## Доменные факты

Дорого добытые знания о данных и окружении. Сюда заносить всё, что можно забыть и переоткрывать заново.

**Данные стран (restcountries.com API v3.1):**
- Запрос требует параметр `?fields=...`, иначе 400.
- Названия стран: `translations.rus.common` — русский, есть для всех 250 стран.
- Столицы в API — **только английские**. Русский словарь — `data/capitals_ru.json` (ключ `cca2`).
- Покрытие `capitals_ru.json` — все 246 столиц из API. Стран без столицы (`hasCapital` false) — 4. Фильтрация по столице игроков из игры не выкидывает.
- Флаги — **локальные `img/flags/{cca2}.svg`** (скачаны `scripts/download_assets.js` из flagcdn.com, коммитятся в репо). Рантайм CDN не дёргает. Фолбэк рендера `svg → png → эмодзи` (`localAssetImg` в ui.js). `flags.svg`/`flags.png` в countries.json остаются как справочник URL для скрипта.
- `country.region` — одно из `Europe / Asia / Africa / Americas / Oceania` (+ `Antarctic` — 5 сущностей, не используем). **Запрашивается через `?fields=...,region`** — без этого поля `country.region` приходит `undefined` и фильтр по регионам не работает (грабли из задачи #6). Распределение: Africa 59, Americas 56, Europe 53, Asia 50, Oceania 27.
- **Лимит `/all`: максимум 10 полей в `?fields=`**, иначе `HTTP 400` (`"requesting more than 10 fields"`). Нам нужно 11 → **скрипт `scripts/fetch_countries.js`** делает **два запроса** (7 полей + 5 полей, оба с `cca2`) и сливает по `cca2` (грабли из задачи #9). Рантайм этих запросов больше не делает — читает готовый `data/countries.json` (отказ от API в рантайме, #25).
- `languages` — объект `{ code: name }`, значения **на английском**. Покрытие 249/250.
- `currencies` — объект `{ code: { name, symbol } }`, значения на английском. Берём первую запись. 247/250.
- `area` — число (км²). Фактически у всех 250 > 0, но фильтруем `> 0` защитно.
- `coatOfArms` — `{ svg, png }` (URL CDN mainfacts.com — справочник в countries.json). Есть у **222** из 250; у остальных — пустой объект. Гербы скачаны локально в `img/coats/{cca2}.svg`; рендер `prompt.type === "coa"` через `localAssetImg("coats", …)`, фолбэк `svg → png → 🏛`.
- `name.nativeName` — `{ langCode: { common, official } }`, уже в поле `name` (отдельный запрос не нужен). Не-английское самоназвание есть у 210/250; `hasNativeName` отсеивает чисто англоязычные.

**Окружение:**
- ES-модули **не работают через `file://`** — нужен локальный сервер. Деплой на GitHub Pages работает.
- Целевые браузеры: десктоп Chrome/Edge/Firefox + Safari на iPad (на нём играет дочка Алексея).
- Тестируем открытием https://vkassu.github.io/GeoGame/ после деплоя. **Кеш браузера** — известная проблема: после деплоя обязательно Ctrl+Shift+R, либо положиться на cache-busting в `index.html` (`?v=...` на script и link).

**Дополнения от Claude Code:**

Слой данных:
- Эндпоинт `/all` отдаёт ~250 сущностей — это **не только суверенные государства**, но и зависимые территории (Гонконг, Реюньон, Гибралтар, Фолкленды, Аруба и т.д.). 246 со столицей; **4 без столицы** — `AQ` Антарктида, `MO` Макао, `BV` Остров Буве, `HM` Остров Херд и о-ва Макдональд (в режимах со столицей не участвуют, фильтр `hasCapital`).

Это не ошибки — при сверке учитывать.

**Правила git:**
- Все эти файлы лежат в репозитории (не в `.gitignore`).
- **После любого нетривиального изменения `.md`-файлов** — Claude Code делает `git commit` с понятным сообщением (`docs: обновлён статус — фича X выполнена`, `docs(reference): убраны статусные пометки`, и т. п.) в той же сессии, когда правка сделана.

Деплой на gh-pages начинается с пуша; держать локальные коммиты бессмысленно. Исключения, при которых сначала спрашиваем: деструктивные операции (`--force`, `reset`, `rebase` с правкой опубликованной истории) и заведомо WIP/неполные коммиты, где push был бы преждевременным.
- Cowork может редактировать `.md`-файлы, но `git commit` не делает. Если Cowork внёс правки — в чате оставляет маркер `⚠ требуется commit`, Claude Code увидит при следующем заходе и закоммитит сам.
- Перед сложными правками — `git status` и `git pull` на чистоту дерева.
