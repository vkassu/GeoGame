# BUGS.md — активные баги, косяки, риски

Живой список. **Открытые** баги вверху, **закрытые** — внизу с датой закрытия.

Приоритеты:
- 🔴 **блокер** — игра не играется или ломается; чинить срочно
- 🟡 **косяк** — UX-неприятность или техдолг, не блокирует игру
- 🟢 **мелочь** — можно отложить надолго

**Формат записи:**

```
### [🔴/🟡/🟢] Краткое название
- **Что не так:** описание
- **Где:** файл / строка / механика
- **Симптом:** что видит/получает игрок
- **Найдено:** YYYY-MM-DD, кем (Алексей / Cowork / Claude Code)
- **Предложенный фикс:** опционально
- **Связано с:** PROMPTS_LOG #N, BACKLOG, и т.п.
```

Новые записи — вверху своей секции. Когда баг закрыт — переносим в «Закрытые» с датой и кратким «как починили».

## Активные

### 🟡 Кнопка подсказки и таймер «висят» в обучении
- **Что не так:** в режиме обучения `#hint-btn` остаётся disabled (серый, но видимый), а `#q-timer` — пустая ячейка с пустым текстом. Строка `.meta` выглядит криво: 3 элемента, один пустой, один серый.
- **Где:** `js/main.js` → `showTrainingQuestion()` (`setHintButtonState(false)` + `timerEl.textContent = ""`); `index.html` → `.meta`.
- **Симптом:** при повторе ошибок наверху неаккуратная шапка.
- **Найдено:** 2026-05-26, Cowork (саморевизия после реализации Обучение+Бонус).
- **Предложенный фикс:** скрыть `.meta` целиком через `display:none` в режиме обучения (CSS-класс `.training-mode` на `#game-screen`, в нём `.meta { display: none }`).
- **Связано с:** PROMPTS_LOG #22.

### 🟡 Заголовок Training при 0 ошибок звучит странно
- **Что не так:** если в партии 0 ошибок, экран Training сразу в финальном состоянии с заголовком «Обучение закончено!». Игрок ничего не проходил, но ему говорят «закончено».
- **Где:** `js/ui.js` → `renderTrainingScreen()`.
- **Симптом:** дёрганная формулировка после идеальной партии.
- **Найдено:** 2026-05-26, Cowork.
- **Предложенный фикс:** при `remaining === 0` и пустом `wrongAnswers` — использовать ключ `training.no-errors` («Идеальная партия!» / «Без ошибок — забирай бонус»). Ключ уже добавлен в `i18n.js`, но не используется. Для этого надо передавать в `renderTrainingScreen` ещё один флаг — было ли изначально ошибок 0, или их закрыли в процессе.
- **Связано с:** PROMPTS_LOG #22.

### 🟡 `info-btn` упадёт в обучении если `.answer-actions` станет видимой
- **Что не так:** в обучении я скрыл всю `.answer-actions` через `display:none`. Сейчас безопасно. Но `showInfo()` читает `state.questions[state.currentQuestion]`, который в обучении не актуален (там `state.trainingCurrent`). Если кто-то когда-то покажет кнопки — info-btn упадёт.
- **Где:** `js/main.js` → `showInfo()`.
- **Симптом:** скрытый риск; сейчас не воспроизводится, но бомба замедленного действия.
- **Найдено:** 2026-05-26, Cowork.
- **Предложенный фикс:** в `showInfo` проверять `state.isTraining` и брать `state.trainingCurrent.country` в этом режиме.
- **Связано с:** PROMPTS_LOG #22.

### 🟡 `aspect-ratio: 1/1` не работает на старых iOS Safari (< 15.4)
- **Что не так:** ячейки бонусной сетки используют `aspect-ratio: 1/1` для квадратной формы. Safari iPad < 15.4 не поддерживает — ячейки схлопнутся в полоску.
- **Где:** `css/style.css` → `.bonus-cell { aspect-ratio: 1 / 1; }`.
- **Симптом:** на старом iPad дочки бонусная сетка может выглядеть сломанной.
- **Найдено:** 2026-05-26, Cowork.
- **Предложенный фикс:** уточнить версию iOS у дочки. Если старая — заменить на `padding-top: 100%` + абсолютное позиционирование внутреннего контента. Иначе оставить.
- **Связано с:** PROMPTS_LOG #22.

### 🟡 Firestore синхронизация только в `endGame()` — риск потери прогресса
- **Что не так:** XP пишется в localStorage по ходу партии, но в Firestore — только в `endGame()`. Если игрок закроет вкладку в середине партии, заработанный XP не попадёт в облако. При следующем входе с другого устройства облако вернёт устаревшие данные и перезапишет ими локальный прогресс.
- **Где:** `js/main.js` → `endGame()`.
- **Симптом:** потенциальная потеря прогресса при кросс-девайс игре с прерванной партией.
- **Найдено:** ~2026-05-24, отмечено в CLAUDE.md «Техдолг» (перенесено сюда 2026-05-26).
- **Предложенный фикс:** дебаунс-сохранение в Firestore каждые N вопросов или раз в M секунд внутри `handleAnswer`. Учесть лимиты Firestore (1 запись в сек на документ — норм).

## Закрытые

### ✅ 2026-05-25 — `resetProgress()` не обновлял меню после сброса
Не вызывал `refreshMenuScreen()` → бар XP/уровень оставались старыми, пока не уйдёшь и не вернёшься. Добавлен вызов в конец `resetProgress`. PROMPTS_LOG #21.

### ✅ 2026-05-25 — `animateXPBar` срабатывал level-up только один раз за партию
При 2+ переходах уровня за одну партию сообщение «Новый уровень!» показывалось только для первого. Заменён `levelUpFired` на `lastFiredLevel`. PROMPTS_LOG #21.

### ✅ 2026-05-25 — Подсказка прятала кнопки через `visibility:hidden`
На сложностях 6/8/10 вариантов скрытые кнопки оставляли дыры в сетке. Заменено на `display:none` + сетка `repeat(2, 1fr)`. PROMPTS_LOG #21.
